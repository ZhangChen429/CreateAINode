# 时序编排 AI（Temporal Orchestration AI）产品方案

> 这不是一个"写剧情"的 AI，而是一个**把剧情和导演意图转成可执行时序**的生产工具。

---

## 一、产品本质定义

本产品本质上不是聊天机器人，而是一个**时序编排 AI（Temporal Orchestration AI）**。

**目标用户**

- 任务设计师
- 叙事设计师
- 过场导演
- 关卡脚本策划
- NPC 行为编排人员

**核心解决的问题**

- 谁先做什么
- 谁和谁并行
- 谁等谁
- 什么信号触发什么
- 被打断后怎么办
- 整段节奏是否自然

**统一处理的五种关系**

| 关系类型 | 说明 |
|---------|------|
| 文本意图 | 导演/策划的自然语言描述 |
| 图结构 | 动作节点与连线 |
| 时间关系 | 先后顺序与时长 |
| 同步关系 | 并行与等待 |
| 中断规则 | 打断与恢复路径 |

---

## 二、产品定位：三层结构

### 第一层：AI 时序助手

> *Copilot for Scene Timing*

最容易落地的切入点。

**用户输入示例**
- "Hanako 先坐下，V 两秒后坐下，等两人都坐稳再开始对话"
- "服务员上酒和镜头推进并行，但台词开始前要完成倒酒"
- "如果玩家提前起身，就打断这段对话并切到追问分支"

**系统输出**
- 时间建议
- 依赖关系
- wait / signal 建议
- 中断规则草案
- 可视化时间轴

---

### 第二层：AI 场景编排器

> *从自然语言生成场景流程图*

输入完整剧本或导演描述，输出 Scene Graph 草图。

**输出内容包括**
- 节点与连线
- 并行 / 串行关系
- 等待点
- 动作候选
- 时间估算
- 可打断点建议

---

### 第三层：AI 时序运行分析器

不直接生成，而是分析现有内容，告诉设计师：

- 这段节奏太紧
- 这里有隐性死等
- 这个信号没有消费者
- 两个动作物理冲突
- 某段等待过长
- 中断后无法回收状态
- 某角色在 3 秒内被分配了互斥动作

> **注：** 这一层对工业化最重要，也最容易进入生产流程。

---

## 三、核心卖点

### 卖点 1：把"逻辑关系"翻译成"可执行时序"

普通 AI 生成的是文本，本产品生成的是**可验证、可执行、可回放、可调试**的时序结构。

### 卖点 2：让策划不再手动处理复杂同步

高价值痛点举例：
- 两人坐下后再说话
- 镜头推进和表情切换同步
- 音乐 cue 和角色动作对齐
- 某个动作被玩家打断后的恢复

### 卖点 3：提供"节奏感"层面的 AI 辅助

很多工具只做逻辑正确，不做节奏美感。真正难的是：
- 太快不自然
- 太慢没张力
- 等待点放错
- 并行关系太乱

### 卖点 4：人机协作，而非替代策划

产品定位是：**AI 先给出时序草案，设计师审核和微调**，而不是"AI 替你做掉设计"。这能明显降低商业推广阻力。

## 四、产品形态方案

### 方案 A：编辑器插件（最推荐）

集成到现有工具（UE / Unity / 自研 Scene Editor / 节点编辑器）作为侧边栏 AI 助手。

**能力**
- 从文本生成节点草案
- 为选中节点生成 timing
- 自动补 wait / signal
- 检查时序冲突
- 生成中断建议

**优点**：最容易融入现有流程 / 最容易验证真实需求 / 最容易收费

---

### 方案 B：Web 端"时序白板"

独立产品，不绑定引擎，优先验证概念。

**输入**：文本剧本 / CSV 动作表 / 动画时长库 / 角色与资源约束

**输出**：Timeline / DAG 图 / 信号依赖图 / 可导出 JSON / Graph

**优点**：演示效果强 / 容易做 ToB Demo / 易于验证概念

---

### 方案 C：离线分析工具

先分析现有 scene，而非先生成。

**能力**：读入已有 graph / execution stream，做诊断并给出改进建议、找 bug 和不自然点。

**优点**：风险最低 / 不碰核心运行时 / 直接提升生产效率

## 五、功能分层架构

```
┌─────────────────────────────────────────┐
│  L5  展示与编辑层                         │
│      时间轴 / 图结构 / 冲突诊断 / AI解释   │
├─────────────────────────────────────────┤
│  L4  求解 / 编译层                        │
│      时间轴 / DAG / 同步点 / 导出格式      │
├─────────────────────────────────────────┤
│  L3  中间表示层（Execution Intent Model） │
│      Action / Dependency / WaitCondition │
│      Signal / InterruptPolicy / TempoHint│
├─────────────────────────────────────────┤
│  L2  理解层（AI 核心）                    │
│      意图解析 / 依赖推断 / 冲突判断        │
│      自然语言 DSL → Temporal IR           │
├─────────────────────────────────────────┤
│  L1  输入层                               │
│      文本描述 / 半结构化表单 / 已有图结构   │
└─────────────────────────────────────────┘
```

### L3 中间表示层详解（产品壁垒核心）

不让 LLM 直接吐最终引擎格式，而是先定义自己的中间层：

| 字段 | 含义 |
|------|------|
| `Action` | 动作节点 |
| `Dependency` | 依赖关系 |
| `WaitCondition` | 等待条件 |
| `Signal` | 触发信号 |
| `InterruptPolicy` | 中断策略 |
| `TempoHint` | 节奏提示 |
| `RecoveryPath` | 恢复路径 |

> **核心原则：AI 负责猜意图，算法负责保证一致性。**

## 八、核心护城河

### 1. 时序领域模型
抽象层对 action / wait / trigger / interrupt / recovery / parallel / ownership / exclusivity 的完整建模，比"接一个大模型 API"重要得多。

### 2. 时长与行为知识库
- 动画时长数据库
- 常见动作组合模板
- 节奏模板库
- 对话转场模式
- 角色行为约束规则

### 3. 验证器
工业工具的必备模块，自动检查：
- 循环等待
- 永不触发的信号
- 互斥动作重叠
- 中断悬空
- 无恢复路径
- 时间负值 / 非法偏移

### 4. 可解释性
用户必须清楚知道：
- 为什么这样排
- 依据了哪些资源
- 哪些是规则推断，哪些是 AI 猜测
- 哪些地方需要人工确认

## 九、产品 Slogan 方向

**偏技术**
- 把叙事意图编译成可执行时序
- 从场景描述到可运行 Timeline
- AI-native Scene Orchestration

**偏设计工具**
- 不用手排毫秒，直接编排场景节奏
- 让 AI 帮你搭好场景时序骨架
- 把导演语言变成场景流程

**偏工业化**
- 为交互叙事提供可验证的 AI 时序编排
- 让场景设计从"画图"升级到"意图驱动"

## 十、落地路径

```
Phase 1  时序分析器 + 时序建议器
         ↓ 风险低，价值直接，快速拿到真实反馈

Phase 2  文本 → 时序草案
         ↓ 生成 Action + Dependency + Timing（暂不碰复杂中断）

Phase 3  信号 / 同步点自动补全
         ↓ 自动生成 wait/signal 建议，可视化给设计师确认

Phase 4  文本 → Scene Graph 草图
           完整产品化版本
```
