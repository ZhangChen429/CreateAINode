# 交互式场景系统文档集 - 总导航
> 从2077提炼的通用叙事系统设计指南

---

## 📚 文档集概览

本文档集提供了一套**与具体引擎无关**的交互式场景系统设计理念，适用于任何需要平衡叙事与交互的游戏项目。

### 核心理念

**我们不教你"2077是怎么做的"，而是教你"为什么要这样做"以及"你该怎么做"。**

## 📊 核心概念速查

### 什么是Tier系统？

```
定义：
  分级的玩家控制权管理系统

核心思想：
  自由度不是开关，而是刻度盘
  0%────────50%────────100%
  完全控制       对话       完全自由

详见：
  - 通用设计模型 → 模型3
  - 实践决策指南 → Tier配置工作坊
```

---

### 什么是场景图？

```
定义：
  用节点和连接表达叙事逻辑的数据结构

核心思想：
  叙事 = 图，而非线性脚本
  支持分支、循环、并行

详见：
  - 通用设计模型 → 模型4
  - 设计原则与反模式 → 反模式6（假选择）
```

---

### 什么是执行流？

```
定义：
  时间轴上的事件序列

核心思想：
  将复杂叙事拆解为时间戳+动作
  支持确定性回放和合成

详见：
  - 通用设计模型 → 模型2
```

---

### 什么是中断系统？

```
定义：
  处理玩家不可预测行为的容错机制

核心思想：
  玩家"破坏"叙事 ≠ 失败
  而是触发替代分支

详见：
  - 通用设计模型 → 模型5
  - 设计原则与反模式 → 原则4
```

## 🎨 设计模式速查

### 模式：逻辑外套 (Logic Overcoat)

```
问题：如何不改底层系统就添加叙事？
方案：在现有系统上添加逻辑层

详见：通用设计模型 → 第四部分 → 模式1
```

---

### 模式：堆栈式状态管理

```
问题：多个系统同时请求控制权怎么办？
方案：用堆栈管理，栈顶优先

详见：通用设计模型 → 第四部分 → 模式3
```

---

### 模式：软约束引导

```
问题：如何引导但不强制？
方案：用"力场"而非"墙"

详见：
  - 通用设计模型 → 第四部分 → 模式4
  - 设计原则与反模式 → 原则3
```

## 🚫 反模式速查

### 强制传送 (Forced Teleportation)

```
错误：黑屏+传送玩家
后果：破坏空间连续性

详见：设计原则与反模式 → 反模式1
```

---

### 长时间硬锁定 (Prolonged Hard Lock)

```
错误：8分钟Tier4场景
后果：玩家感觉"坐牢"

详见：设计原则与反模式 → 反模式2
```

---

### 隐形墙对话

```
错误：用隐形墙防止玩家离开
后果：暴露技术限制

详见：设计原则与反模式 → 反模式3
```

---

### 过度自动化

```
错误：自动完成所有操作
后果：玩家成为观众

详见：设计原则与反模式 → 反模式4
```

---

### 上下文丢失

```
错误：场景后状态重置
后果：因果连续性破坏

详见：设计原则与反模式 → 反模式5
```

---

### 假选择

```
错误：选项都指向同一结果
后果：违反玩家信任

详见：设计原则与反模式 → 反模式6
```

## 🎯 常见问题解答

### Q1: 我的游戏是TPP，还需要这个系统吗？

```
答案：视情况而定

需要，如果：
  ✅ 叙事是核心玩法
  ✅ 追求沉浸式体验
  ✅ 玩家有很大自由度

可选，如果：
  ⚠️ 传统过场也能满足
  ⚠️ 叙事占比较低

不需要，如果：
  ❌ 纯动作/竞技游戏
  ❌ 无叙事需求

详见：实践决策指南 → 决策树
```

---

### Q2: 这个系统开发成本高吗？

```
答案：取决于实现范围

最小可行版本（2-4周）：
  - 基础Tier系统
  - 简单场景图
  - 序列执行

完整版本（2-6个月）：
  - 5层Tier + 编辑器
  - 复杂场景图 + 分支
  - 中断系统 + 预加载

推荐：从最小版本开始，迭代扩展

详见：实践决策指南 → 迭代优化指南
```

---

### Q3: 如何说服团队采用这个架构？

```
答案：展示问题和收益

准备材料：
  1. 现有方案的痛点（反模式）
  2. 新方案的优势（设计原则）
  3. 实现路线图（可行性）
  4. 行业案例（证明）

详见：本文档 → "我需要说服团队"章节
```

---

### Q4: 我可以只实现部分功能吗？

```
答案：可以，推荐分阶段实现

优先级：
  P0（必须）：
    - Tier系统（至少3层）
    - 基础场景图

  P1（重要）：
    - 距离中断
    - 预加载系统

  P2（增强）：
    - 复杂中断条件
    - 回放支持
    - 可视化编辑器

详见：实践决策指南 → 最小可行实现
```
