# 赛博朋克2077 群体AI系统（Community System）架构分析

## 一、.community文件的结构与定义

### 1.1 文件作用
`.community`文件是2077中定义群体AI（非玩家角色批量生成）的核心资源文件，用于控制：
- **何时**生成NPC（时间段）
- **哪里**生成NPC（Workspot位置）
- **生成什么**NPC（角色类型）
- **生成多少**NPC（数量）

### 1.2 文件结构（基于二进制格式）
```
communityCommunityTemplate
├── communityTemplate (handle:communityCommunityTemplateData)
    ├── entries[] (array:handle:communitySpawnEntry)
    │   ├── entryName (CName) - 条目名称，如"guard_01"
    │   ├── characterRecordId (TweakDBID) - 角色记录ID，如"Character.q201_arasaka_security"
    │   ├── phases[] (array:handle:communitySpawnPhase)
    │   │   ├── phaseName (CName) - 阶段名称，如"spawn"
    │   │   ├── appearances[] (array:CName) - 外观列表
    │   │   ├── timePeriods[] (array:communityPhaseTimePeriod)
    │   │   │   ├── hour (ECommunitySpawnTime) - 时间段（Morning/Day/Evening/Night）
    │   │   │   ├── quantity (Uint16) - 该时间段生成数量
    │   │   │   ├── markings[] (array:CName) - 标记/分类
    │   │   │   ├── spotNodeRefs[] - Workspot节点引用
    │   │   │   └── isSequence (Bool) - 是否按顺序使用spots
    │   │   └── alwaysSpawned (Bool) - 是否始终生成
    │   └── initializers[] (array:handle:SpawnInitializer)
    │       ├── SquadInitializer - 小队初始化器
    │       ├── PatrolInitializer - 巡逻初始化器
    │       └── VoiceTagInitializer - 语音标签初始化器
    └── crowdEntries[] (array:CrowdTemplateEntry) - 人群模板条目
```

### 1.3 示例解析
从`q201_guards_alley.community`文件中可以看到：
- 定义了19个守卫条目（guard_01 ~ guard_19）
- 所有守卫使用相同的角色记录：`Character.q201_arasaka_security`
- 每个条目有一个"spawn"阶段
- 系统会根据时间段和位置动态生成这些守卫

## 二、Community System核心架构

### 2.1 系统层次结构
```
CommunitySystem (游戏系统)
├── CommunitiesMap - 所有Community实例的集合
│   └── Community (单个群体实例)
│       ├── CommunityTemplate (模板数据) - 从.community文件加载
│       └── CommunityEntry[] (条目实例)
│           ├── BaseCommunityEntry (基类 - 状态管理)
│           │   ├── 当前Phase
│           │   ├── 当前TimePeriod
│           │   └── Active状态
│           └── CommunityEntrySpawner (生成器)
│               ├── EntityStubSet - 实体存根集合
│               ├── SpawnedObjectsDeathCounter - 死亡计数器
│               └── StaticCommunityAppearancesPicker - 外观选择器
├── CommunityTimePeriodsManager - 时间段管理器
├── CommunityWorkspotsMarker - Workspot标记管理器
├── CrowdSystem2 - 人群系统
├── SpawnerManager - 生成器管理器
└── EntityStubsOrphanage - 孤儿实体存根管理器
```

### 3.4 EntityStub生成机制
**文件位置**: `common/gamePopulation/src/communityEntrySpawner.cpp`

```cpp
bool CommunityEntrySpawner::CreateEntityStub(...) {
    // 1. 选择Workspot
    AI::SpotUsageToken spotToken;
    if (has workspots) {
        spotToken = workspotMgr.TryUseSpot(spotNodeId);
    }

    // 2. 创建EntityStub
    EntityStubCreationTokenHandle tokenHandle =
        stubSystem.RequestStubCreation(
            recordId,
            worldPosition,
            spawnInView
        );

    // 3. 保存待处理数据
    m_pendingEntityStubsCreationData.EmplaceBack(
        spotToken,
        tokenHandle
    );

    // 4. 回调处理
    // OnEntityStubCreatedOrRestored() 将在stub创建完成后被调用
    //   ├── 设置Appearance
    //   ├── 应用Initializers
    //   └── 添加到EntityStubSet
}
```

### 3.5 时间段切换机制
**文件位置**: `common/gamePopulation/src/communityEntry.cpp`

```cpp
void CommunityEntry::OnCurrentTimePeriodChanged() {
    // 1. 获取当前Phase
    const SpawnPhase* currPhase = m_data.GetPhase(GetCurrentPhaseName());

    // 2. 获取当前TimePeriod
    const PhaseTimePeriod* currPeriod =
        currPhase->GetTimePeriod(m_currentTimePeriodHour);

    // 3. 更新Spawner参数
    m_spawner->ChangeSpawnParameters(*currPhase, *currPeriod);
    //   ├── 删除多余的EntityStub
    //   ├── 创建新的EntityStub
    //   └── 更新Workspot分配
}
```

## 七、性能优化机制

### 7.1 分帧更新
```cpp
void CommunitySystem::Update(job::Builder& builder, Float deltaTime) {
    // 1. 处理待处理请求（分时处理）
    ProcessPendingRequests(loadingScreenMode);

    // 2. 更新Community（并行）
    for (auto& community : m_communities) {
        builder.DispatchJob([&]() {
            community->Update();
        });
    }

    // 3. 更新Crowd系统
    m_crowdSystem->UpdateDistantCrowd(deltaTime);
}
```

### 7.2 流式加载优化

## 九、总结

### 9.1 核心设计模式
1. **模板-实例模式**: `.community`文件定义模板，运行时创建实例
2. **分层架构**: System -> Community -> Entry -> Spawner -> EntityStub
3. **时间驱动**: 基于游戏时间自动切换Phase和TimePeriod
4. **空间驱动**: 基于Area流式加载Workspot数据
5. **对象池模式**: EntityStub的提取和归还机制

### 9.2 群体AI实现的关键要素
1. **模板数据**（.community文件）定义"规则"
2. **时间系统**控制"何时"生成
3. **Area系统**控制"何处"生成
4. **Workspot系统**提供"具体位置"
5. **Initializer系统**赋予"AI行为"
6. **Spawner系统**执行"实际生成"

### 9.3 优势
- **数据驱动**：设计师可以通过编辑.community文件配置NPC
- **性能可控**：分帧更新、流式加载、数量限制
- **灵活性高**：支持多阶段、多时间段、动态切换
- **可扩展性**：Initializer系统支持自定义行为

### 9.4 应用场景
- **开放世界人群**：街道上的行人、商贩、守卫
- **任务场景**：特定区域的敌人、NPC
- **时间相关**：白天/夜晚不同的NPC分布
- **动态事件**：基于游戏状态切换Phase
