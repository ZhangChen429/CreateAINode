## 执行摘要（Executive Summary）

> **核心结论**：2077的AI群组系统通过**三层架构**（AttitudeGroup-Squad-Community）和**10+系统整合**，实现了从全局派系关系到具体战术协同的完整AI群组管理方案，支持开放世界的动态叙事需求。

**关键成果**：
- ✅ 支持5-20人小队的战术协同作战
- ✅ 实现全游戏世界的派系关系网络
- ✅ 动态多阶段叙事场景管理
- ✅ 行为树共享机制节省84-88%内存

**适用场景**：
- 开放世界RPG
- 剧情驱动游戏
- 需要复杂群体AI的3A游戏

# 第一部分：黄金圈法则 - WHY（为什么）

## 1.1 核心问题：为什么需要AI群组系统？

### 🎯 游戏设计目标（Why We Built This）

```
问题陈述：
传统游戏AI是"个体智能"，每个NPC独立思考、独立行动。
但2077的设计目标是什么？

答案：
"让玩家相信Night City是一个活生生的世界，
 每个帮派、每个公司都有自己的势力范围，
 NPC不是孤立的个体，而是组织的一部分，
 他们会为了组织的利益协同作战。"

这就是AI群组系统存在的根本原因。
```

### 2.2 技术实现路径（How It Works）

#### 路径1️⃣：派系关系网络（AttitudeGroup Layer）

```cpp
// HOW: 如何定义全局派系关系？

// 方法：TweakDB关系矩阵 + AttitudeManager运行时管理

// TweakDB定义（数据驱动）
AttitudeRelation {
    sourceGroup: "Arasaka"
    targetGroup: "Militech"
    attitude: Hostile      // 敌对
}

AttitudeRelation {
    sourceGroup: "Arasaka"
    targetGroup: "NCPD"
    attitude: Friendly     // 友好
}

// 运行时查询（系统接口）
IAttitudeManager::GetGlobalAttitude(
    srcGroup: "Arasaka",
    dstGroup: "Militech"
) → Hostile

// 结果：
// → Arasaka守卫看到Militech士兵会自动进入战斗
// → 无需为每个NPC单独配置敌友关系
```

**设计亮点**：
- ✅ 数据驱动：关系矩阵在TweakDB中配置，无需硬编码
- ✅ 全局一致性：整个游戏世界使用同一套关系网络
- ✅ 动态覆盖：支持临时态度覆盖（任务中临时改变派系关系）

#### 路径2️⃣：战术协同层（Squad Layer）

```cpp
// HOW: 如何让NPC协同作战？

// 方法：Squad系统 + Order机制 + Event广播

// Step 1: 创建Squad
SquadManager.CreateSquad({
    name: "checkpoint_alpha",
    type: SquadType::Combat,
    template: "MilitarySquad"
})

// Step 2: 成员加入Squad
Squad.AddMember(guard_01)
Squad.AddMember(guard_02)
Squad.AddMember(guard_03)

// Step 3: 事件广播
guard_01.OnSpotEnemy(player)
  → Squad.BroadcastEvent(EnemySpotted, player)
  → guard_02.OnSquadEnemySpotted(player)  // 收到通知
  → guard_03.OnSquadEnemySpotted(player)  // 收到通知

// Step 4: 战术命令
SquadLeader.IssueOrder({
    type: TakeCover,
    target: guard_02,
    position: coverPos
})
  → guard_02.OnGiveOrder(TakeCover)
  → BehaviorTree.SwitchTo("TakeCover")

// 结果：
// → 一人发现敌人，全队知晓
// → 队长可以指挥成员执行战术
// → 成员之间信息共享（敌人位置、战术状态）
```

**设计亮点**：
- ✅ 松耦合：Squad不依赖具体的NPC类型，只依赖SquadMemberBase接口
- ✅ 可扩展：新增战术只需扩展Order类型
- ✅ 类型安全：7种SquadType满足不同需求（Combat/Community/Security等）

#### 路径3️⃣：场景管理层（Community Layer）

```cpp
// HOW: 如何管理场景中的所有NPC？

// 方法：.community文件 + Phase系统 + TimePeriod系统

// .community文件定义
{
    "entries": [
        {
            "entryName": "day_guard",
            "characterRecordId": "Character.guard_standard",
            "phases": [
                {
                    "phaseName": "normal",
                    "timePeriods": [
                        { "hour": "Day", "quantity": 5 }    // 白天5个守卫
                    ]
                },
                {
                    "phaseName": "alert",
                    "timePeriods": [
                        { "hour": "Day", "quantity": 15 }   // 警报时15个守卫
                    ]
                }
            ],
            "initializers": [
                { "type": "SquadInitializer", "squad": "checkpoint_alpha" }
            ]
        },
        {
            "entryName": "night_guard",
            "characterRecordId": "Character.guard_veteran",
            "phases": [
                {
                    "phaseName": "normal",
                    "timePeriods": [
                        { "hour": "Night", "quantity": 8 }  // 夜晚8个老兵
                    ]
                }
            ],
            "initializers": [
                { "type": "SquadInitializer", "squad": "checkpoint_alpha" }
            ]
        }
    ]
}

// 运行时控制
CommunitySystem.SetCurrentPhase("alert")
  → 删除5个day_guard
  → 创建15个day_guard
  → 所有guard自动加入"checkpoint_alpha" Squad
  → 场景从"正常巡逻"切换到"高度警戒"

// 结果：
// → 一行代码切换整个场景状态
// → 自动管理NPC生命周期
// → 支持多阶段剧情推进
```

**设计亮点**：
- ✅ 设计师友好：可视化编辑，无需编程
- ✅ 性能优化：流式加载、延迟创建、自动清理
- ✅ 叙事支持：Phase切换驱动剧情发展

## 2.3 系统整合方案（System Integration）

### 10+系统整合架构图

```
┌────────────────────────────────────────────────────────────────┐
│                     CommunitySystem                            │
│                   (场景级NPC管理)                              │
└────────────────────────────────────────────────────────────────┘
                            │
                            │ GetSystem<>()
                            │
        ┌───────────────────┼───────────────────┐
        │                   │                   │
        ▼                   ▼                   ▼
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│ 生成与生命周期│    │ AI行为与感知 │    │ 战斗与战术   │
└──────────────┘    └──────────────┘    └──────────────┘
        │                   │                   │
        │                   │                   │
┌───────┴─────────┐  ┌──────┴──────────┐  ┌────┴─────────┐
│1.PopulationSys  │  │4.BehaviorTree   │  │7.SquadMgr    │
│2.EntityStubSys  │  │5.SenseMgr       │  │8.AttitudeMgr │
│3.PersistencySys │  │6.TargetTracker  │  │9.InfluenceMap│
│4.WorkspotMgr    │  │                 │  │10.CombatSpace│
└─────────────────┘  └─────────────────┘  └──────────────┘
```

### 整合策略详解

#### 整合1️⃣：生成层整合（Creation Layer）

```
CommunitySystem 如何整合生成系统？

流程：
1. CommunitySystem.ActivateEntry()
   ├── 计算需要生成的NPC数量
   └── 准备生成位置（Workspot或随机）

2. EntityStubSystem.RequestStubCreation()
   ├── 创建轻量级EntityStub
   └── 延迟实例化（性能优化）

3. WorkspotManager.TryUseSpot()
   ├── 尝试占用工作点
   └── 标记为已使用

4. PopulationSystem.SpawnEntity()
   ├── 将EntityStub实例化为Entity
   └── 加载资源（模型、动画、AI）

5. PersistencySystem.SaveState()
   ├── 存档NPC状态
   └── 支持Save/Load

整合价值：
✓ 延迟创建：EntityStub占用少量内存，按需实例化
✓ 流式加载：玩家靠近才生成，离开自动卸载
✓ 状态持久化：NPC死亡后不复活（除非Phase切换）
```

#### 整合2️⃣：AI行为层整合（Behavior Layer）

```
CommunitySystem 如何整合AI系统？

流程：
1. CommunityEntry指定characterRecordId
   └── TweakDB.Character_Record定义AI参数

2. Character_Record引用AI::Archetype
   └── Archetype引用BehaviorTree

3. BehaviorTree在运行时执行
   ├── 每个NPC有独立的BehaviorTreeInstance
   └── 但共享.behavior文件资源（节省84%内存）

4. SenseManager监听感知事件
   ├── OnEnemyDetected() → 通知Squad
   └── OnAllyDamaged() → 通知Squad

5. TargetTrackerManager追踪敌人
   ├── 每个NPC的TargetTrackerComponent
   └── Squad成员共享目标信息

整合价值：
✓ 行为复用：多个NPC共享同一.behavior文件
✓ 感知共享：Squad成员共享感知信息
✓ 目标共享：CombatSquad统一管理敌人列表
```

#### 整合3️⃣：战斗层整合（Combat Layer）

```
CommunitySystem 如何整合战斗系统？

流程：
1. CommunityEntry通过Initializer配置Squad
   └── SquadInitializer("checkpoint_alpha")

2. SquadManager创建或查找Squad
   ├── FindSquad("checkpoint_alpha")
   └── 如果不存在，CreateSquad()

3. Squad.AddMember(npc)
   ├── NPC加入Squad
   └── 开始接收Squad事件

4. AttitudeManager定义派系关系
   ├── GetGlobalAttitude(srcGroup, dstGroup)
   └── 决定敌友关系

5. CombatSquad战术协调
   ├── InfluenceMapSystem.CreateLayer() → 战术地图
   ├── CombatSpaceManager.FindCover() → 掩体查询
   └── NavigationSystem.FindPath() → 路径规划

6. 战术执行
   ├── Squad.IssueOrder() → 下达命令
   ├── Member.OnGiveOrder() → 接收命令
   └── BehaviorTree执行战术行为

整合价值：
✓ 战术深度：InfluenceMap提供空间感知
✓ 协同作战：Squad命令系统协调成员
✓ 派系关系：AttitudeGroup定义敌友
```

# 第五部分：如何推进叙述（Narrative Progression）

## 5.1 叙事系统整合架构

```
┌────────────────────────────────────────────────────┐
│            SceneSolution（场景解决方案）           │
│          剧情设计师的核心工具                      │
└────────────────────────────────────────────────────┘
                        │
                        │ 包含
                        │
        ┌───────────────┼───────────────┐
        │               │               │
        ▼               ▼               ▼
┌──────────────┐ ┌──────────────┐ ┌──────────────┐
│CommunityNodes│ │DialogNodes   │ │TriggerNodes  │
│场景NPC控制   │ │对话树        │ │触发条件      │
└──────────────┘ └──────────────┘ └──────────────┘
```

### 叙事节点类型

#### 节点1️⃣：CommunityActivate（激活社区）

```cpp
// SceneSolution中的CommunityActivate节点

scnsExecutableItem_Community {
    spawnerReference: "base/quest/main_quests/part1/q115/q115_arasaka_tower.community"
    entryNames: ["lobby_guard", "receptionist"]
    phaseName: "infiltration"
}

// 执行效果：
communitySystem.SetCurrentCommunityEntryPhase(
    communityId,
    "lobby_guard",
    "infiltration"
)
communitySystem.ActivateCommunityEntry(communityId, "lobby_guard")

// 叙事意义：
// → 玩家进入荒坂大楼，场景切换到"潜入"阶段
// → 大厅守卫按"潜入"阶段的配置生成
// → 守卫警戒等级为"低"
```

#### 节点2️⃣：CommunityPhaseChange（切换阶段）

```cpp
// SceneSolution中的PhaseChange节点

// 触发器：玩家被发现
if (player.isDetected) {
    communitySystem.SetCurrentPhase("alarm_triggered")
}

// .community文件中的Phase定义
{
    "phaseName": "infiltration",
    "timePeriods": [
        { "hour": "Day", "quantity": 4 }  // 4个守卫
    ]
},
{
    "phaseName": "alarm_triggered",
    "timePeriods": [
        { "hour": "Day", "quantity": 15 }  // 15个守卫（增援）
    ]
}

// 叙事意义：
// → 玩家触发警报
// → 场景从"潜入"切换到"警报"
// → 守卫数量从4个增加到15个
// → 剧情自然推进到"战斗阶段"
```

#### 节点3️⃣：AttitudeChange（改变派系关系）

```cpp
// SceneSolution中的AttitudeChange节点

// 剧情：玩家帮助Militech，Arasaka敌对
attitudeManager.SetTemporaryGlobalAttitude(
    "Arasaka",
    "Player",
    EAIAttitude::Hostile
)

attitudeManager.SetTemporaryGlobalAttitude(
    "Militech",
    "Player",
    EAIAttitude::Friendly
)

// 叙事意义：
// → 所有Arasaka NPC自动敌对玩家
// → 所有Militech NPC自动友好玩家
// → 全游戏世界关系改变
// → 玩家感受到"选择的后果"
```

#### 节点4️⃣：SquadOrder（小队命令）

```cpp
// SceneSolution中下达Squad命令

// 剧情：指挥官命令小队撤退
squad.IssueSquadOrder({
    action: "Retreat",
    target: "extraction_point",
    priority: High
})

// 所有Squad成员收到命令
for (member in squad.members) {
    member.OnGiveOrder("Retreat")
    member.BehaviorTree.SwitchTo("RetreatBehavior")
}

// 叙事意义：
// → NPC表现出"接到命令后撤退"的组织化行为
// → 不是逃跑（个体行为），而是撤退（组织行为）
// → 玩家看到NPC的"智能"和"纪律"
```

## 5.2 叙事推进的5个层次

### 层次1️⃣：对话驱动叙事（Dialog-Driven）

```
传统方式：
├── 玩家与NPC对话
├── 对话选项影响剧情
└── 通过对话传递信息

AI群组增强：
├── 对话结束后，CommunityPhaseChange
├── 场景NPC立即响应对话结果
└── 示例：
    对话："我们撤退！"
    → SetCurrentPhase("retreat")
    → 所有NPC开始撤退动画和行为
```

### 层次2️⃣：事件驱动叙事（Event-Driven）

```
触发机制：
├── 玩家触发Trigger
├── SceneSolution执行节点
└── Community/Squad/Attitude响应

示例：q110任务（Voodoo Boys）
├── Event: 玩家进入教堂
│   → CommunityActivate("voodoo_church", "peaceful")
│   → 2个守卫在门口，和平状态
│
├── Event: 玩家与Placide对话
│   → Dialog场景播放
│   → 对话结束后Phase保持
│
├── Event: 玩家进入禁区
│   → SetCurrentPhase("hostile")
│   → 守卫立即敌对
│   → 增援生成
│
└── Event: 战斗结束
    → SetCurrentPhase("aftermath")
    → 尸体保留，清理人员生成
```

### 层次3️⃣：时间驱动叙事（Time-Driven）

```
TimePeriod自动切换：
├── Morning（6:00）：城市苏醒
│   ├── 商贩开始营业
│   ├── 公司员工上班
│   └── 帮派成员回据点休息
│
├── Day（9:00）：正常运转
│   ├── 街道繁忙
│   ├── 警察巡逻增多
│   └── 帮派活动减少
│
├── Evening（17:00）：下班高峰
│   ├── 员工下班
│   ├── 酒吧开始营业
│   └── 帮派活动增加
│
└── Night（22:00）：夜生活
    ├── 流浪汉占据街道
    ├── 帮派活动高峰
    └── 警察加强巡逻

叙事意义：
→ 世界随时间自然变化
→ 玩家感受到"活着的城市"
→ 不同时间段有不同的体验
```

### 层次4️⃣：空间驱动叙事（Space-Driven）

```
Area流式加载机制：
├── 玩家进入Area
│   → Community流入
│   → NPC生成
│   └── 场景激活
│
├── 玩家离开Area
│   → Community流出
│   → NPC卸载
│   └── 状态保存
│
└── 再次进入Area
    → 加载保存的状态
    → 死亡的NPC不复活
    → 保持世界一致性

示例：Maelstrom据点
├── 第一次进入：完整的帮派（20人）
├── 玩家击败他们后离开
├── 再次进入：
│   ├── 尸体还在（PersistencySystem）
│   ├── 活着的成员还在
│   └── 不会刷新新的成员
│
叙事意义：
→ 玩家的行动有持久影响
→ 世界状态可持久化
→ "我清理了这个据点"是有意义的
```

### 层次5️⃣：派系驱动叙事（Faction-Driven）

```
AttitudeGroup关系网络：
├── 初始状态：
│   ├── Arasaka ↔ Player: Neutral
│   ├── Militech ↔ Player: Neutral
│   └── Arasaka ↔ Militech: Hostile
│
├── 剧情选择1：帮助Militech
│   └── SetTemporaryGlobalAttitude("Arasaka", "Player", Hostile)
│       → 所有Arasaka NPC敌对
│       → 所有Arasaka检查站攻击玩家
│       → 全游戏世界关系改变
│
└── 剧情选择2：帮助Arasaka
    └── SetTemporaryGlobalAttitude("Militech", "Player", Hostile)
        → Militech全面敌对
        → 改变后续任务的NPC反应

叙事意义：
→ 选择有全局性后果
→ 派系关系影响整个游戏
→ 玩家感受到"选边站"的压力
```
